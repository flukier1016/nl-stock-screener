# 所以然 · 一句话选股

> **不只给名单，也讲清为什么。**
> 把“经营改善、估值合理、走势相对稳定”这样的模糊想法，变成看得见、改得动、查得到出处的数据条件，
> 用同花顺金融数据 API（扶摇）的真实数据筛出候选股票，并解释每只股票为什么入选、为什么被排除、条件变了会怎样。

- **在线体验**：https://mingshai-production.up.railway.app （真实数据）
- **分享一句话**：`/?q=经营改善、估值合理、走势相对稳定&run=1` 打开即自动解析并筛选
- **演示数据**：`/?data=demo`（合成数据，股票名带“演示”，没有 Key 时也能体验流程）
- **演示视频**：158 秒，在线上站点真实操作录制（提交附件 `04_演示视频.mp4`；制作脚本见 `scripts/demo_video/`）
- **一句话设计**：大模型只把话翻译成条件，确定性引擎出结果，每个数字回到扶摇原始字段。

## 1. 三十秒看懂

```
一句话 ──► ① 解析：切片段，映射到口径字典（大模型；失败退回规则）
            │      守门器：只能用字典里的概念/指标/行业，越界整条拦下并展示原因
            ▼
         ② 澄清：每个模糊词给 2～3 种可执行口径，默认推荐项；做不到的口径也列出来并说明原因
            ▼
         ③ 条件：可编辑的条件表 + 股票池；实时提示冲突、口径不适用、张力、缺数据比例
            ▼
         ④ 筛选：确定性引擎逐股逐条判定 通过 / 不通过 / 缺失 → 入选 · 差一点 · 被排除 · 数据缺失
            │      逐条漏斗；每个条件“去掉它多出几只”；阈值扫描曲线（点一下就改阈值重跑）
            ▼
         ⑤ 解释与后续：证据卡（事实 / 推断 / 不确定）· 对比 · 保存 · 转为监控 · 导出 · AI 白话解读（过数字守门器）
```

三条契约：

| 契约 | 怎么兑现 |
|---|---|
| **AI 只翻译** | 大模型输出被 JSON Schema 约束，再逐片段过 `guard.check_segment`；不允许输出股票代码、公司名或任何关于具体公司的数字 |
| **引擎出结果** | 筛选、计数、敏感度全是 pandas 向量化计算；同一策略 + 同一快照 → 同一个 `run_id`，测试保证可复现 |
| **数字有出处** | 证据卡里每个值都带来源接口、字段、报告期或窗口、单位、数据时点，以及扶摇返回的 `request_id` |

## 2. 题目要求逐条对照

| 题目要求 | 实现 | 页面位置 / 代码 |
|---|---|---|
| 自然语言意图的**澄清** | 每个模糊概念 2～3 个口径方案（推荐项 + 可选项），另列“做不到的口径”及原因（如“低于自身历史估值分位”：扶摇估值只有最新快照）；AI 复述理解、列出待确认问题 | 第 2 步 · `registry.py` `parse_llm.py` |
| **结构化条件** | `Strategy`（股票池 + 条件列表）纯 JSON，可序列化、可哈希、可保存 | 第 3 步 · `dsl.py` |
| **冲突识别** | 同一指标区间无交集（必然 0 只）、股票池互斥、口径不适用（负债率筛银行）、概念张力（用真实数据算“各自满足几只、同时满足几只”）、缺数据比例过高 | 第 3、4 步 · `conflicts.py` |
| **条件修改** | 表格内改指标 / 比较符 / 阈值 / 基准（绝对值、行业中位数、全市场中位数）；增删条件；在敏感度曲线上点选阈值；改动后旧结果标“已过期” | 第 3、4 步 |
| **AI / 引擎 / 数据工具职责边界** | 见第 4 节 | `parse_llm.py` / `engine.py` / `data/` |
| **入选 / 排除依据** | 证据卡逐条列实际值、阈值（相对阈值写明中位数和可比公司数）、差多少、计算展开（如 ROE 年化 = 原值 × 2） | 点任一行 · `explain.py` |
| **数据口径、时点、缺失** | 顶栏与结果头部写明估值快照时点、行情截止日、财务报告期；缺失单独成组，**不按通过处理** | 顶栏 / “数据缺失”分组 |
| **条件变化的影响** | 逐条漏斗；每个条件“去掉它多出几只 + 会多出谁”；阈值扫描曲线；结果太少时给出最近的放宽点 | 第 4 步右栏 |
| **比较、保存、回测或转监控** | 对比（2～5 只，含股票池分位）、保存策略、转为监控（快照更新后重跑，记录新进入 / 移出及原因）、导出 CSV；回测见“未做事项” | 第 4、5 步 · `monitors.py` |
| **合规边界** | 预测涨跌、收益承诺、买卖建议、目标价类表达在解析阶段拒绝并给出可验证的替代说法；整句只有这类内容时规则层直接拒绝、不调用大模型（合规前置）；AI 解读过合规检查；页脚声明 | `registry.REFUSE_PATTERNS` `parse_llm.parse` |
| **事实 / 推断 / 不确定区分** | 证据卡三栏分开 | 证据卡底部 |
| **数据缺失、冲突、过期、调用失败不得静默** | 没有真实快照时接口返回 503，页面不出任何结论；构建失败不替换旧快照；监控遇到同一快照明确写“没有新数据”；相对阈值样本不足记为缺失 | `store.py` `data/build.py` |

## 3. 产品选择：为什么这样做

**目标用户**：有选股想法、但不会（或不想）把想法写成精确条件的个人投资者，以及需要给客户解释“为什么是这几只”的投顾和研究助理。

**要解决的问题**：

1. 同一个模糊词，不同人、不同工具的口径完全不同（“估值合理”是 PE < 30，还是不高于行业中位数？），而现有的一句话选股常常不告诉你它用了哪个口径；
2. 结果是一张名单，看不到每只股票卡在哪、差多少，也不知道换个阈值会怎样；
3. 缺数据的公司常被悄悄当成“满足”或悄悄消失。

**做法**：把“理解”交给大模型，把“判断”交给可审计的确定性引擎，两者之间放一个人能读懂、能修改的条件表。
大模型擅长处理口语、同义词、英文混写（评测里规则解析对口语句子 0 分，见第 7 节），但它不碰任何数字。

**非目标**：不做涨跌预测、不排名推荐、不给买卖建议；不追求覆盖所有选股维度，而是保证覆盖到的每个维度口径清楚、出处可查。

## 4. AI、引擎、数据工具的职责边界

| 角色 | 做什么 | 不做什么 | 失败时 |
|---|---|---|---|
| **大模型**（`llm.py` `parse_llm.py`） | 把一句话切成片段，映射到口径字典的概念 / 方案 / 指标 / 行业；选推荐方案；识别要拒绝的片段；写白话解读 | 不选股、不计算、不输出公司名和关于公司的数字、不访问数据 | 超时、非法 JSON、未配置 → 自动退回规则解析，页面写明原因；白话解读未通过数字守门或合规检查 → 整段丢弃，展示原因和被拦下的草稿 |
| **守门器**（`guard.py`） | 只放行字典里存在的 id；数值必须在指标合法范围内；相对阈值不能用区间 | 不“帮大模型改对” | 拦下的片段逐条展示 |
| **确定性引擎**（`engine.py` `conflicts.py`） | 股票池过滤、逐股逐条三态判定、分组、漏斗、去掉条件的影响、阈值扫描、冲突与张力计数 | 不调用大模型、不联网 | 数据缺失 → “缺失”状态；可比公司不足 5 家 → 缺失 |
| **数据工具**（`data/fuyao.py` `data/build.py`） | 从扶摇取数，写台账，构建快照，原子替换 | 不做判断 | 限流退避重试；业务错误原样抛出；任一步失败不替换旧快照，状态写进 `build_state.json` 并在页面显示 |

## 5. 数据来源与口径

全部来自**同花顺金融数据 API（扶摇）**，鉴权 `X-api-key`：

| 用途 | 接口 |
|---|---|
| 代码表、上市日期、ST 标记 | `GET /api/meta/tickers/list?asset_type=a-share` |
| 行业（同花顺行业指数，自动识别层级，取覆盖率 ≥ 80% 的最细一级） | `GET /api/a-share-index/catalog/ths-index-list?tag=industry` + `.../constituents/ths-stock-list` |
| 股票池与大中小盘代理（沪深 300 / 中证 500 / 中证 1000） | `GET /api/a-share-index/constituents/ths-stock-list` |
| 估值（PE TTM、PB MRQ、PS TTM、PCF TTM） | `GET /api/a-share/valuations/snapshot`（每次 100 只） |
| 财务比率：ROE、毛利率、净利率、负债率、流动比率、现金含量（2026 中报、2025 中报） | `GET /api/a-share/financials/indicators` |
| 营收、归母净利润原始金额与披露日（最近 9 个季度，用来自算增速） | `GET /api/a-share/financials/income-statements?period=quarterly` |
| 日 K（未复权）、近 10 日增量、除权除息事件 | `GET /api/dump/market-dumps/{daily-k, daily-k-10d, adjustment-factors}/download-url` |
| 交易日历（核对行情是否最新） | `GET /api/a-share/calendar/trading-days` |

**口径决策**（都写在 `registry.py`，引擎、解释卡、守门器、前端共用这一份）：

- **增速用利润表自算**：扶摇财务指标接口的营收、净利润同比字段实测全为空（抽查 8 只、三个报告期），
  所以营收同比、归母净利润同比、二季度单季同比（累计值相减）都用利润表原始金额计算，证据卡展示金额和公式；
  利润同比的分母取上年同期绝对值（亏损收窄、扭亏记为正增长），分母为 0 或营收 ≤ 0 时记为缺失。
- **报告期统一用 2026 中报**：三季报正在披露，混用会让同一条件比较的不是同一段时间；证据卡提示“若三季报已在快照后披露，结论可能变化”。
- **ROE 年化**：原始字段是半年数据，展示为“原值 × 2”，证据卡同时给出原值。
- **行业中位数**：同花顺行业分组，只统计该指标有效（估值类只取正值）的非 ST 公司，可比公司不足 5 家记为缺失；参照池不随股票池变化。
- **大中小盘**：扶摇暂无市值字段，用沪深 300 / 中证 500 / 中证 1000 成分股代理，页面写明。
- **复权**：按除权除息事件自行推导参考价（扶摇约定的“原始数据为主”）；构建时体检除权日收益率，若 |r| > 25% 的占比超过 5%（单位理解错误的典型症状）就停止构建。
- **股息率**：近 365 天除息日的税前现金分红合计 ÷ 最新收盘价；尚未实施的预案不计入。

**取数纪律**：每次请求写入 `data/ledger.jsonl`（接口、参数、HTTP 状态、业务 code、request_id、条数、耗时，不含 Key）；
只对限流和上游暂时不可用做有限次退避重试；原始返回存 `data/work.duckdb` 支持断点续跑；快照先写临时文件，校验通过后原子替换。

## 6. 启动方式

```bash
uv venv --python 3.12 && uv pip install -e ".[dev]"
cp .env.example .env          # 填扶摇 Key 文件路径；大模型可选
.venv/bin/python -m mingshai.data.build --limit 200   # 先取 200 只联调（全量去掉 --limit）
.venv/bin/uvicorn mingshai.app:app --port 5577        # 打开 http://localhost:5577
```

没有任何 Key 也能体验流程：`MINGSHAI_DATA=demo` 启动，或访问 `/?data=demo`（合成数据，页面有 DEMO 横幅）。

部署：仓库带 `Dockerfile` 和 `railway.json`。Railway 上挂一个持久卷到 `/data`，在环境变量里配置 Key；
服务启动后若没有快照会自动构建，之后每个交易日北京时间 16:30 后日更一次，日更完成后自动重跑所有监控任务。

### 环境变量

| 变量 | 说明 |
|---|---|
| `FUYAO_API_KEY` / `FUYAO_API_KEY_FILE` | 扶摇 API Key（或只含 Key 的文件路径） |
| `MINGSHAI_LLM_PROVIDER` | `anthropic` / `openai_compat` / `off`；不填时按 Key 自动判断 |
| `MINGSHAI_LLM_API_KEY` / `MINGSHAI_LLM_API_KEY_FILE` | 大模型 Key |
| `MINGSHAI_LLM_MODEL` | 模型名；Claude 默认 `claude-opus-5-5` |
| `MINGSHAI_LLM_BASE_URL` | OpenAI 兼容接口地址（DeepSeek、通义等） |
| `MINGSHAI_LLM_EFFORT` | Claude 的 effort，默认 `low`（解析任务不需要深度推理） |
| `MINGSHAI_DATA` | `live`（默认）/ `demo` |
| `MINGSHAI_DATA_DIR` | 快照、台账、保存的策略所在目录 |
| `MINGSHAI_AUTO_BUILD` | `1` 时自动构建与日更 |
| `MINGSHAI_ADMIN_TOKEN` | 手动触发构建 `POST /api/admin/build` 的口令 |

## 7. 测试与评测

- `pytest`：60 个用例，覆盖主链路、数据缺失与接口失败、合规拒绝、冲突、可复现性等，详见 [docs/TESTING.md](docs/TESTING.md)。
- `eval/run_eval.py`：33 句意图解析评测（标准说法、口语、写明数字、行业、股票池、拒绝、无法识别）。
  规则 25/33（口语 0/6），Claude `claude-opus-5-5` 32/33（口语 6/6），逐条分析见 [docs/AI_USAGE.md](docs/AI_USAGE.md)。

## 8. 已知边界

- 单季数据由累计值相减得到，个别公司更正过往报表时可能与原始单季披露略有出入。
- 估值接口只有最新快照，无法做“低于自身历史估值分位”，也无法对估值条件做无前视偏差的历史回测。
- 没有市值字段，大中小盘用指数成分股代理。
- 三季报披露期内统一使用中报，个别已披露三季报的公司数据会滞后一期。
- 估值快照时点（可能是盘中）与行情截止日（收盘）可能不同，页面分别标注。
- 监控只在页面记录变化，没有微信 / 邮件推送；保存的策略按浏览器匿名编号区分，没有账户体系。
- 服务托管在 Railway（境外），不收集任何个人信息。

## 9. 未做事项

- **历史回测**：估值没有历史序列，财务指标只取了三个报告期，直接回测会把今天的数据用到过去（前视偏差）。
  宁可不做，也不给出看起来精确、实则有偏的历史收益曲线；后续可用财务报表的披露日（`report_date_ms`）重建时点数据，先支持“行情 + 财务”类条件的回测。
- iFinD MCP 交叉核验（同一指标双源比对，不一致时标出）。
- 更多维度：市值、机构持仓、资金流、单季财务拆分。
- 推送通知与账户体系。

**合规声明**：本项目只按用户设定的条件筛选并解释公开数据，不预测涨跌、不承诺收益、不构成任何买卖建议。
历史数据和当期财务指标不代表未来表现。仓库不包含任何 API Key、用户隐私或扶摇原始数据。
