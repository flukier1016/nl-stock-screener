# 评测范围与证据边界

## 历史开发集

`v1/cases.json`冻结原来的33句及标签。`results/20261015-*.json`是该旧版本、旧评分下的开发记录，不是0.2版的新结果。

当前`cases.json`保留33条输入，并明确修正“分红稳定／每年分钱多”的旧标签：多年一致性归为未支持，不能奖励映射成高股息；股票池冲突增加必须阻止执行的检查。变更记录写在各用例note中，不能与旧评分直接比较。

0.2版`run_eval.py`要求比较符精确相同，基准相同，不额外添加显式条件；每次结果保留完整解析片段。15和15.0是相同数值，`<`和`<=`不是相同条件。概念映射的检查仍然不等同完整金融任务成功率。

```bash
uv run --env-file .env python eval/run_eval.py        # 只跑规则
uv run --env-file .env python eval/run_eval.py --llm  # 有效模型配置与预算允许时；会计费
```

模型密钥失效时不得用规则降级结果冒充模型新评测；历史97%不沿用于0.2版。

## 回归验收

`acceptance_cases.json`由本轮复盘发现与明确产品契约编写，覆盖精确边界、行业排除、OR、时间窗口、分红语义、复杂否定和拒绝。它是开发回归集，尚未进行独立、盲态人工标注。

`check_acceptance.py`对支持的输入比较完整条件集合、包含与排除行业；对未支持输入检查明确的拦截原因。名单部分使用4只手工构造股票，其中一只上市日期缺失；5组期望名单人工计算，验证严格比较、行业排除、时间窗口与缺失处理。

```bash
.venv/bin/python eval/check_acceptance.py --output build/acceptance.json
```

每份结果记录用例文件SHA256、完整期望、实际策略、拦截原因和运行编号。回归通过仅表示已知要求没有退化，不意味着真实用户任务成功率100%。

## 下一轮独立验证

由未参与开发的目标用户提供自然表达，再由两位具金融知识的标注者分别给出完整条件、期间、逻辑和应拒绝部分。冻结输入与标签后再运行，记录分歧；不因看到模型输出而修改标签。新增合理解释时建立新版本并保留原始评分。

分别报告全量任务成功率、支持范围内成功率、严重语义错误率、错误放行与错误拒绝、证据一致率、延迟及每个成功任务的调用成本。不得把被安全拦截的全部样本计为成功任务。真实用户执行方案见`docs/USER_RESEARCH.md`。
