# 运行验收与恢复

## 本地验收

```bash
.venv/bin/python -m pytest -m 'not llm and not live'
.venv/bin/python eval/check_acceptance.py --output build/acceptance.json
.venv/bin/ruff check --select F mingshai eval tests
node --check mingshai/static/app.js
```

测试使用临时额度账本和构造数据，不调用真实模型或扶摇。39条意图验收和5组手算名单是回归测试，不能表述为真实用户准确率。

本地服务请显式加载环境文件：`uv run --env-file .env uvicorn mingshai.app:app --port 5577`。演示模式使用`MINGSHAI_DATA=demo`并关闭自动构建；演示股票和时点会明确标注。

## 数据与AI状态

`/api/health`的HTTP200表示进程仍能响应；`data_ready`表示存在通过质量检查的真实快照，`status=degraded`和`data_warning`表示服务降级。不要把进程存活当作完整任务可用。

AI状态分为：未配置、已配置待验证、最近调用成功、鉴权失败、临时失败及额度切断。只有实际成功调用后才显示健康；401/403后不反复发送相同无效凭据。更换配置后进入待验证状态；成功调用才恢复AI标签。

当前财务报告期固定为2026中报。数据修复或服务部署不会自动将财务口径更新为三季报。

## 快照发布规则

股票数、代码唯一性、必需字段与关键覆盖率在写入前检查。上市天数有效覆盖率低于98%时拒绝新快照；少量上市日期缺失的股票归入无法判断，不能当作上市不足一年。

质量不合格时保留上一份通过校验的快照；重启也重新验证前驱文件。正常数据保存在`snapshot.duckdb`，健康前驱保存在`snapshot.prev.duckdb`，被拒绝的原文件保存在数据目录`rejected/`。这些文件不进公开仓库。

现场检查发现批量代码表的`list_date`可能整体为空，即使HTTP与业务code均成功。上市日期是可以保留历史来源的元数据：优先使用本次非空日期，否则仅按完整股票代码沿用之前合格快照的原始日期，逐行记录来源快照与请求编号。新股或未保存日期仍然缺失，不猜测。页面明确提示缓存来源；行情、估值与财务时点不会因此被标为最新。没有任何可信历史日期时，质量契约继续阻止发布。

管理接口使用已有Bearer管理口令：`GET /api/admin/snapshot`用于备份，`POST /api/admin/snapshot`用于经过质量校验的上传，`POST /api/admin/repair-listings`仅重新向扶摇核验上市日期并重算上市年限。修复保留行情、估值、财务原有时点，记录元数据请求编号。修复失败保留原文件。

部署后如果发现现有快照未通过校验，自动构建开启时会先尝试一次上市日期核验，避免直接进行全量财务取数。应检查页面与返回状态，确认真实股票池不再被缺失字段清空。

## 失效模型密钥

在部署平台的加密变量中更新`MINGSHAI_LLM_API_KEY`，保持原有`MINGSHAI_LLM_API_KEY_FILE`。启动过程将有效配置写入受保护的文件；不要通过聊天、公开仓库、命令行参数或截图传递密钥。随后用一条支持范围内的普通输入验证实际调用及健康状态。

额度上限与累计花费继续沿用原账本。更换密钥不重置预算，也不能通过更换提供方规避总额切断；额度不足时继续按已声明的规则模式运行。

## 发布后的最低检查

1. 打开产品查看版本、数据时点、AI实际状态。
2. 运行一个普通筛选，确认默认上市年限后的股票池合理且字段覆盖率合格。
3. 输入“不要银行股，股息率高于3%”，确认行业是剔除。
4. OR、20日波动率和多年分红稳定性必须明确暂停执行。
5. 查看一只样本的证据；保存、比较与监控同样执行意图校验。
6. 核对旧快照、匿名保存策略和额度账本保留；出现异常可回滚部署，数据恢复也需通过同一质量契约。
