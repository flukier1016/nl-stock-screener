# 产品选择与验证计划

版本：0.2。以下用户需求和效果均为待验证假设；尚未完成真实用户研究。

## 最先服务谁

有基本财务指标知识、每周整理观察股票池的个人投资者。核心任务是把模糊想法变成自己理解的条件，检查候选与排除原因，保存并持续跟踪这组条件。第一阶段不以预测涨跌、投资收益或替用户交易作为价值指标。

## 要验证的价值

假设：自然语言输入加显式口径确认，能降低建立可解释观察池的时间与误解率。需要与相同数据、相同指标的手工条件表比较，不能仅凭页面完整或解析返回200就判断有效。

| 选择 | 原因 | 代价与验证方式 |
|---|---|---|
| 模型理解语言、程序筛选 | 数值计算、股票名单与条件影响可以重复验证 | 需要验证模型是否保留完整意图，不能只验证JSON合法 |
| AND与行业排除先做完整 | 原有列表引擎只能准确表达同时满足 | OR、复杂否定和不支持的期间先明确阻止执行；后续条件树要同时改造漏斗、影响和解释 |
| 财务统一2026中报 | 比较相同统计期 | 不接受用户指定三季报后仍使用中报；季度口径列为未支持 |
| 显式列出默认阈值 | 用户能检查和更改产品假设 | 3%股息率、PE15等是启发式模板，尚无用户研究或收益证据证明最优 |
| 行业中位数作为相对参照 | 减少行业结构差异对绝对阈值的影响 | 行业粒度、异常值、样本数与中位数都要可见；“低于同行”不等于经济意义上的低估 |
| 近12个月股息率与多年分红稳定性分开 | 当前现金回报水平和多年一致性含义不同 | 缺少逐年验证前，不将“分红稳定”映射为高股息 |
| AI只选择解释事实编号 | 指标、数值、单位、期间绑定后由程序呈现 | 文案变化较少，但模型无法通过交换已有数字改变事实 |
| 数据质量先于新鲜度 | 坏快照会使可重复计算得到系统性错误结果 | 新数据质量不合格时保留合格旧数据，并明确展示时点与更新失败 |

## 衡量效果

| 指标 | 分子／分母 | 用途 |
|---|---|---|
| 完整任务成功率 | 用户在规定时间内建立语义正确、证据正确并成功保存的策略／全部发起的任务 | 主指标；安全拒绝与降级都不能算完成 |
| 支持范围内任务成功率 | 支持范围内正确完成任务／支持范围内任务 | 与全量任务成功率并列，避免用缩小范围抬高指标 |
| 意图保真率 | 未漏条件、未加条件、逻辑与期间正确的解析／评审样本 | 需要独立人工标注与分歧记录 |
| 严重语义错误率 | 发生否定反转、OR变AND、期间替换的样本／全部样本 | 发布时优先消除；不能被平均通过率掩盖 |
| 证据一致率 | 指标、数值、单位、期间、实体均匹配的陈述／全部陈述 | 数字出现过不代表陈述正确 |
| 首次正确保存用时 | 从读完任务到保存一份正确策略的时间 | 报中位数、范围与失败数；不能用引擎毫秒耗时替代 |
| 缺失与失败可见性 | 被正确阻止、隔离或提示的异常／注入的异常 | 衡量容错，不等同用户价值 |
| 回访使用 | 在约定一周后实际再次使用／可回访参与者 | 待真实跟踪；目前没有留存数据 |

## 下一阶段的产品门槛

先完成线上有效快照、失效密钥提示和严重语义错误回归。随后按USER_RESEARCH.md试用5–8位目标用户，记录至少3类可复现的阻碍，并将改动对应回观察记录。OR条件树、多轮增量修改和季度财务扩展，应根据任务覆盖与失败成本排序。

本仓库的自动化回归是开发验收证据，不能替代独立用户评测、真实留存或经济效果证明。
