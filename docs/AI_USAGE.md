# AI 使用与验证记录

## 1. 用到的 AI 工具

| 用途 | 工具 | 说明 |
|---|---|---|
| 开发 | Claude Code（Claude Opus 5.5） | 读题目与扶摇文档、设计架构、编写代码与测试、起草文档；在浏览器里逐步点验页面 |
| 产品内：意图解析 | 可配置：Claude（默认 `claude-opus-5-5`，`effort=low`）或 OpenAI 兼容接口（DeepSeek / 通义等） | 只做“在口径字典里挑选”，输出受 JSON Schema 约束并逐片段过守门器 |
| 产品内：白话解读 | 同上 | 只能复述引擎给出的事实；写完过数字守门器与合规检查，不通过整段丢弃 |

## 2. AI 参与的环节与验证方式

| 环节 | AI 做了什么 | 怎么验证 |
|---|---|---|
| 读题与选题 | 拆解三道题的交付物与隐含考点，对照作者已有项目给出选题建议 | 人工决策选第 1 题 |
| 读接口文档 | 从扶摇 `llms-full.txt` 整理可用接口、字段、限流与错误码 | 与文档原文逐项核对路径和字段名；不确定的（下载链接返回结构）做成兼容处理并加测试 |
| 口径字典 | 起草 14 个概念、26 个指标的口径方案 | 契约测试：每个方案的条件必须合法、每个概念恰好一个推荐项、同义词不跨概念；人工审口径（见第 3 节） |
| 引擎与解释 | 编写三态判定、分组、漏斗、敏感度、证据卡 | 一致性测试：漏斗末项 = 入选数；“去掉第 i 条多出 N 只”与真正去掉后重跑一致；曲线当前点 = 入选数 |
| 数据管道 | 编写扶摇客户端、快照构建、复权计算 | MockTransport 测试限流、业务错误、重试上限；手算除权日收益率核对；送转单位体检 |
| 前端 | 编写页面 | 在浏览器里逐步走完主链路，检查渲染与交互 |

## 3. 开发中发现并修正的问题

以下都是本项目开发过程中真实出现、经测试 / 评测 / 人工审查发现后修正的，修正后有对应测试兜底。

| # | 问题 | 怎么发现 | 修正 |
|---|---|---|---|
| 1 | “破净”被放进“低估值”概念，默认方案是 PE ≤ 15，语义错了 | 人工审口径 | 改为固定说法：破净 = 市净率 0～1 倍 |
| 2 | “现金流好”方案用 `净利润增速 > −100%` 冒充“净利润为正”，逻辑不成立 | 人工审口径 | 改为 `销售净利率 > 0` |
| 3 | “大于 15%”被解析成 `≥ 15`，与“不低于”混为一谈 | 人工审解析结果 | 严格区分 `<` `<=` `>` `>=` 四类措辞，加测试 |
| 4 | “明天会涨停”只截到“明天会涨”，拒绝理由对、片段不完整 | 浏览器点验 | 正则备选项按长度排序 |
| 5 | “剔除 ST 和次新股”漏掉次新；改写时还撞上 Python 正则不支持变长回看 | 评测集 `excl` 用例失败 | 改为代码里向前查找剔除动词，按出现顺序处理 |
| 6 | 同一概念出现两次（“高速增长的成长股”）在页面重复成两张卡 | 评测输出 | 概念片段按概念去重 |
| 7 | 中报 ROE 是半年数据，直接和“ROE 15%”比较会系统性偏严 | 人工审口径（领域知识） | 明确年化 = 原值 × 2，证据卡同时展示原值 |
| 8 | 三季报披露期混用不同报告期，同一条件比较的不是同一段时间 | 人工审口径（领域知识） | 统一用 2026 中报并在页面写明 |
| 9 | 估值类行业中位数把亏损公司的负 PE 算进去，中位数被拉低 | 人工审口径 | 估值类只统计正值，可比公司不足 5 家记为缺失 |
| 10 | 监控“移出原因”显示成条件编号（“经营改善：c1”），用户看不懂 | 人工审页面文案 | 改为完整条件描述 |
| 11 | 日更时间判断写成“小时 ≥ 16 且分钟 ≥ 30”，17:10 会被跳过 | 代码审查 | 改为比较 (时, 分) 元组 |
| 12 | 演示数据的交易所分配表达式写乱，三分之一是北交所 | 代码审查 | 重写为明确规则 |
| 13 | 右栏“条件变化的影响”过长，把结果表挤到很下面 | 浏览器点验 | 限高并在框内滚动 |

## 4. 产品内大模型的验证

### 4.1 意图解析评测（`eval/run_eval.py`，33 句）

| 解析方式 | 通过 | 标准说法 | 口语 | 英文 |
|---|---|---|---|---|
| 规则 | 25/33 | 25/26 | 0/6 | 0/1 |
| 大模型 | `<待配置 Key 后运行>` | | | |

评分口径：概念集合、写明数字的条件（指标 + 数值 + 方向）、股票池、行业、拒绝与无法识别片段数、剔除项，每条用例只查它写明的项；
另查“没有误拒”（不该拒绝的句子里不能出现拒绝片段）。

### 4.2 守门器

- 大模型输出目录外的概念、越界数值、结构不合法的片段，整条拦下并在页面“守门器拦下了 AI 的 N 条输出”里展示原因（测试 `test_llm_out_of_catalog_is_blocked`）。
- 白话解读：文中每个数字都必须能在引擎结果里找到（千分位、百分比、四舍五入都算对上），且不能出现预测、承诺或买卖建议；否则整段丢弃（测试 `test_number_guard` `test_compliance_guard`）。

## 5. 仍然需要人工判断的地方

- 口径方案本身（什么叫“经营改善”）是产品决策，字典里每个方案都有白话说明，用户可以在澄清面板换掉。
- 行业中位数的分组粒度依赖同花顺行业层级，自动选覆盖率 ≥ 80% 的最细一级，构建日志里记录了各级的组数和覆盖率。
